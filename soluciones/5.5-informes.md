## La prueba que mata los dos del 30

En `backend/tests/Reservas/ReglaDeCapacidadTest.php`:

```php
public function test_una_sala_grande_admite_una_franja_de_diez_y_media_a_once_y_media(): void

    $sala = new Sala('Auditorio', capacidadMaxima: 40);
```

## Infection sobre la regla de capacidad, después

```
.M....M..........
```

```
17 mutations were generated:
      15 mutants were killed by Test Framework
       2 covered mutants were not detected

Metrics:
         Mutation Code Coverage: 100%
         Covered Code MSI: 88%
```

Los dos del 30 han muerto. Quedan los otros dos, y cada uno tiene su respuesta a la pregunta del capítulo:

- **`?? 1` por `?? 0`** es equivalente. `Capacidad` no admite menos de un asistente, así que comparar con 0 o con 1 da siempre lo mismo. Ninguna prueba lo puede matar: se apunta y se deja.
- **El `&&` cambiado por `||`** no es equivalente. Con una sala grande, más asistentes que plazas y una franja en punto, la regla dice que no y el mutante dice que sí. Ninguna prueba pide eso a una sala grande. Si a alguien le importaría ese cambio, falta una prueba, y es un buen candidato para el paso 2 del lab.

## Stryker sobre el formulario de reserva

No se puede lanzar en esta rama, y la rama no lo trae. Con Stryker 10.1.1 y su complemento de Vitest instalados y la configuración del capítulo, la ejecución inicial se para así:

```
ERROR DryRunExecutor One or more tests resulted in an error:
	An error occurred outside of a test run: F:/w/repos/tstcln-reservas/frontend/.stryker-tmp/sandbox-j63GBW/src/app/reservas/formulario-reserva/formulario-reserva.spec.ts: describe is not defined
```

Stryker lanza Vitest directamente, sin pasar por `ng test`, y la configuración que Angular monta por dentro no está en ningún fichero. Con un fichero de configuración propio de Vitest (globales, jsdom y `TestBed` preparado), las pruebas del formulario siguen sin arrancar, porque falta el compilador de Angular:

```
Error: Component 'FormularioReserva' is not resolved:
 - templateUrl: ./formulario-reserva.html
 - styleUrl: ./formulario-reserva.css
Did you run and wait for 'resolveComponentResources()'?
```

Es la incidencia abierta de Stryker con Angular. En el curso se queda como limitación conocida, y la práctica de mutación se hace con Infection.

La prueba del mensaje general sí va en la solución, porque comprueba un comportamiento que ninguna otra miraba: un fallo que no es un rechazo enseña «No se ha podido hacer la reserva». En `frontend/src/app/reservas/formulario-reserva/formulario-reserva.spec.ts`:

```typescript
it('enseña el mensaje general si la reserva falla por otro motivo', async () => {
  const crear = vi.fn(() => throwError(() => new Error('Http failure response: 500')));
  await render(FormularioReserva, {
    inputs: { sala: salaNorte },
    providers: [{ provide: ApiReservas, useValue: { crear } }],
  });
  const usuario = userEvent.setup();

  await usuario.type(screen.getByLabelText('Persona'), 'Ana');
  fireEvent.input(screen.getByLabelText('Hora de inicio'), { target: { value: '2027-03-04T10:00' } });
  fireEvent.input(screen.getByLabelText('Hora de fin'), { target: { value: '2027-03-04T11:00' } });
  await usuario.click(screen.getByRole('button', { name: 'Reservar' }));

  expect(await screen.findByText('No se ha podido hacer la reserva')).toBeTruthy();
});
```
